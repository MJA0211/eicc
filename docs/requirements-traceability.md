## Full lifecycle proof

`tests/test_workflow.py::test_complete_business_need_to_release_workflow` creates a fresh project and follows
Business Need → BR → FR → TR → Systems → Integration → Mapping → Test → Actual Failure → Defect → Mapping
Correction → Passing Retest → Resolved Defect → UAT Evidence → Stakeholder Approval → Impact-Assessed Change →
Completed Change → Release → All Mandatory Gates → Completed Release. It also changes acceptance criteria and
checks that the prior approval becomes stale.

Browser verification uses the real API without route mocks. Authoring and SOAP investigation are exercised in
`workspace.spec.ts`. `governance.spec.ts` provisions a separate fictional scope through the API, then performs
UAT results, attachment upload, stakeholder decision, change assessment and approval, and release transitions
through the actual user interface.

## Evidence limits

An axe scan of the dashboard is not a comprehensive accessibility certification. Chromium tests do not assert
compatibility with every browser. SQLite and PostgreSQL runs cover the application suite; they are not load,
failover, penetration, or disaster-recovery certification. See [verification](verification.md) for observed results.
